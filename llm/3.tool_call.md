# Tool Calling / Function Calling

## 1. The Core Flow
LLM can only generate text — no hands, no internet. Tool calling lets it REQUEST your code do something, then use the result.

1. Define a JSON schema describing a function (name, description, params)
2. Send schema + messages to the model
3. Model returns a "tool call" (function name + args) instead of text — it does NOT execute anything itself
4. Your code executes the real function, gets a real result
5. Feed the result back into the messages array as a new message
6. Model now answers using that result

**Why step 5 is required:** model is stateless — it only knows what's literally in the messages array. If you don't feed the tool result back, it has no way of knowing what happened, since it never actually ran the function itself.

**Simple words (phone call story):** LLM = smart voice on the phone with no hands. It asks you "please check the weather app for Paris." You check it, tell them what you saw. Only then can they actually answer — they were never able to see your screen themselves.

**Interview answer:** "Tool calling works by giving the model a JSON schema of available functions. When needed, the model returns a structured tool call request instead of free text — it never executes anything itself. The developer's code runs the actual function, and the result is appended back into the messages array, since the model is stateless and only knows what's explicitly in its context."

## 2. The Agent Loop (Core Skill)
```python
while True:
    response = llm(messages, tools)
    if response.tool_calls:
        for call in response.tool_calls:
            result = execute(call)
            messages.append(tool_result(result))
    else:
        return response.text
```

- `while True`: keep looping — model may need several tool calls before it can answer
- `llm(messages, tools)`: call the model with full conversation + list of available tools
- `if response.tool_calls`: did the model ask for a tool instead of answering directly?
- `for call in ...`: handle each requested tool call (can be multiple at once)
- `execute(call)`: YOUR code actually runs the real function
- `messages.append(tool_result(result))`: tell the model what happened, so next loop iteration it has that info
- `else: return response.text`: model didn't need a tool this time — done, give the final answer

**Simple words:** ask the model → did it ask you to check something? → if yes, check it, tell it, ask again → if no, it's ready to answer for real.

**Interview answer:** "The agent loop repeatedly calls the LLM with the current message history and available tools. If the model requests a tool call, the application executes the real function and appends the result to the messages array, then loops again — since the model needs that result in context to proceed. Once the model responds with plain text instead of a tool call, the loop exits and that text is returned as the final answer. LangGraph and other agent frameworks are essentially structured orchestration around this same loop."
